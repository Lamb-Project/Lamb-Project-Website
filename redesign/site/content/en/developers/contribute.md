Start at the [LAMB source repository](https://github.com/Lamb-Project/lamb). Read the instructions in the revision you are working with and check existing issues before starting a large change.

## Report an issue people can reproduce

Include the version or commit, the relevant user role, the action taken, the expected result and what happened. Use a small synthetic example when possible. Remove keys, session-bearing URLs, learner identities and private course material from screenshots and logs.

Separate “the request failed” from “the requested object was not created.” If a request timed out, inspect the saved state before retrying or reporting a duplicate.

## Propose a change

Explain the user-visible problem and the resulting behaviour. Include the tests appropriate to the change and say which environment you checked. Coordinate the target branch with maintainers: a development line is not automatically the release line.

For a suspected vulnerability, check the repository's current security-reporting instructions or contact its maintainers privately before posting sensitive details publicly.

## Documentation and translation

Documentation contributions should name the version they describe and preserve the distinction between a working capability and a proposal. Update a screenshot and its steps together when the interface changes. The website's English redesign is a draft; Spanish, Catalan and Basque will need equivalent task coverage.
